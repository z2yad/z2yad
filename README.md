## 🚀 Featured Projects

### 🛒 Rendering — Angular E-Commerce Platform

<a href="https://e-commerce-iota-sand.vercel.app/"><img src="https://img.shields.io/badge/🔗_Live_Demo-e--commerce--iota--sand.vercel.app-000000?style=flat-square&logo=vercel"/></a>
&nbsp;
<a href="https://github.com/z2yad/E-commerce"><img src="https://img.shields.io/badge/Source_Code-GitHub-181717?style=flat-square&logo=github"/></a>
&nbsp;
<img src="https://img.shields.io/badge/Status-In_Progress-f59e0b?style=flat-square"/>

> A production-level e-commerce platform demonstrating full-stack engineering maturity — from architecture decisions to UI micro-interactions.

<details>
<summary><b>⚡ Technical Deep-Dive (click to expand)</b></summary>
<br/>

**🔴 Problem**
Modern e-commerce needs fast initial loads for SEO, reactive state for cart/checkout UX, and a maintainable codebase that can scale from prototype to production.

**🟡 Solution**
- **SSR via `@angular/ssr`** — server-renders critical routes for SEO-optimized page loads
- **Per-route rendering strategy** — SSR for product listing/detail (SEO), CSR for cart/checkout (interactivity)
- **Reactive cart service** — powered by Angular Signals + RxJS for real-time state across components
- **Production-grade Express/MongoDB backend** — JWT refresh token rotation, role-based access control, Helmet.js, rate limiting, Swagger docs, and Sharp-powered image optimization
- **spartan/ui + Tailwind CSS 4** — OKLCH color spaces, glassmorphism, fully custom design tokens
- **Route guards on checkout** — prevents invalid state navigation, ensuring data integrity
- **PrimeNG admin panel with Chart.js** — feature-rich dashboard with real-time analytics visualizations

**🟢 Impact**
Deployed to Vercel with measurable SSR performance. Backend has already migrated off the original mock API onto a production Node.js/Express/MongoDB service — architecture stays flexible for a Java/Spring Boot service layer as that stack comes online.

</details>

<br/>

| Layer | Technology | Purpose |
|:---|:---:|:---|
| Framework | Angular 21 | Component architecture, routing, DI |
| Rendering | `@angular/ssr` | SEO + performance |
| Backend | Node.js + Express + MongoDB | REST API, auth, data persistence |
| Auth | JWT refresh rotation + RBAC | Secure, role-aware session handling |
| Styling | Tailwind CSS 4.2 + spartan/ui | Design system tokens |
| Notifications | `ngx-sonner` | Toast feedback layer |
| Testing | Vitest 4.1 | Unit test coverage |
| Deployment | Vercel | CI/CD + edge deployment |

<img src="https://img.shields.io/badge/Status-In_Development-f59e0b?style=flat-square"/>
&nbsp;
<img src="https://img.shields.io/badge/Angular-Multi--Tenant_SaaS-DD0031?style=flat-square&logo=angular&logoColor=white"/>

> A multi-tenant B2B CRM architected around a provisioning-first model — no public sign-up; accounts are issued only through a paid subscription, the way real enterprise SaaS products actually gate access.

<details>
<summary><b>⚡ Technical Deep-Dive (click to expand)</b></summary>
<br/>

**🔴 Problem**
Most CRM side-projects ship with open registration and a flat data model — neither reflects how B2B SaaS products actually control access or isolate tenant data.

**🟡 Solution**
- **Provisioning-based architecture** — no public registration; admin accounts are provisioned only on a paid subscription, matching real B2B SaaS access patterns
- **34 screens across 9 modules** — planned as the full CRM surface area, not a demo slice
- **`DESIGN.md`-driven UI system** — a documented design system paired with the Uiverse/spartan token approach to keep a large screen count visually consistent

**🟢 Impact**
Demonstrates the ability to architect a large-scale, multi-tenant SaaS product's data and access model before writing a single throwaway screen — systems thinking that separates a CRUD app from an enterprise-ready platform.

</details>

### 🧠 QuizMaster — Secure Quiz Engine

<a href="https://github.com/z2yad/QuizMaster"><img src="https://img.shields.io/badge/Source_Code-GitHub-181717?style=flat-square&logo=github"/></a>
&nbsp;
<img src="https://img.shields.io/badge/Status-Live-22c55e?style=flat-square"/>

> A full-featured SPA quiz platform with a security-first authentication system — built entirely in Vanilla JS, demonstrating core JavaScript mastery without framework abstraction.

<details>
<summary><b>⚡ Technical Deep-Dive (click to expand)</b></summary>
<br/>

**🔴 Problem**
Build a dynamic, multi-category quiz app with secure auth and state management — without any framework.

**🟡 Solution**
- **SHA-256 + unique salt hashing** via Web Crypto API — password security without a backend
- **SPA routing** with Navigo 7 — zero-reload navigation with hash routing
- **OpenTDB API integration** — dynamic questions across 6 categories with error handling
- **Light/Dark mode** — CSS custom properties toggle with LocalStorage persistence
- **Responsive breakpoints** — mobile-first grid from 320px to large displays

**🟢 Impact**
Demonstrates framework-agnostic JavaScript skills, cryptographic security awareness, and clean SPA architecture — all valued signals in a senior interview.

</details>

<br/>

|:---|:---|
| Auth Security | SHA-256 + salt via Web Crypto API |
| Navigation | SPA routing (Navigo 7) — zero reload |

| UI | Light/Dark mode, fully responsive (4 breakpoints) |

### 🧟 DEAD ROAD — 3D Zombie Survival Game

<img src="https://img.shields.io/badge/Status-Personal_Project-a855f7?style=flat-square"/>
&nbsp;
<img src="https://img.shields.io/badge/C%2B%2B-Raylib-00599C?style=flat-square&logo=cplusplus&logoColor=white"/>

> A wave-based 3D zombie survival game built in C++ with Raylib — a deliberate step outside the web stack to sharpen low-level programming and real-time rendering fundamentals.

<details>
<summary><b>⚡ Technical Deep-Dive (click to expand)</b></summary>
<br/>

**🔴 Problem**
Web frameworks abstract away memory management, rendering pipelines, and the game loop — skills worth building hands-on to become a stronger engineer overall.

**🟡 Solution**
- **C++ with Raylib** — a lightweight, close-to-the-metal graphics library, no engine abstraction
- **Wave-based survival mechanics** — enemy spawning, difficulty scaling, and a real-time 3D gameplay loop
- **Integrated 3D models from Quaternius.com**, after evaluating and ruling out Spline for C++ compatibility

**🟢 Impact**
A compact (~614 lines) but complete demonstration of C++ fundamentals, 3D math, and game-loop architecture — proof of range beyond the Angular/web comfort zone.

</details>

<br/>

| Capability | Detail |
|:---|:---|
| Language | C++ |
| Graphics | Raylib |
| Assets | 3D models via Quaternius.com |
| Scope | ~614 lines, wave-based survival loop |
